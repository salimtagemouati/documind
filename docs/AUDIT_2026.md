## Architecture and observations

React/Vite calls FastAPI using application-issued HS256 JWTs, not Supabase Auth tokens (`backend/app/core/security.py:60-116`). The API uses async SQLAlchemy against PostgreSQL or local SQLite, checks ownership in routes and retrieval, stores originals locally or through the Supabase service client, and uses Redis or bounded local memory for cache. PDF/DOCX extraction runs in a thread; chunks are embedded with `gemini/gemini-embedding-001` at 768 dimensions, persisted in pgvector, retrieved by independent dense and PostgreSQL English FTS searches with RRF, optionally reranked, then passed to a LiteLLM generator. SQLite retrieval is a different lexical fallback. Migrations define HNSW and GIN indexes. Stripe signatures are checked; Sentry is optional. Configured generation default is `gemini/gemini-3.5-flash-lite`, reranking is disabled by default (`backend/app/core/config.py:69-100`). This does not prove the deployed settings or secrets.

## Findings

Each item includes failure, remedy, and verification; P1 means release-blocking for a paid, multi-tenant production claim, P2 material quality/reliability, P3 smaller issue. No P0 was proved from source alone.

1. **P1 — quota race, proven by code.** `backend/app/services/stripe_service.py:211-247` reads a counter without locking or reservation; `backend/app/api/routes/query.py:84-153` invokes a paid model before a separate increment and commits twice. Concurrent requests can all pass the same remaining slot and lost updates can undercount. Fix atomic per-user reservation with refund/reconciliation on failure and a single transaction; verify concurrent requests at the boundary against PostgreSQL and crash recovery.
2. **P1 — webhook state can regress, proven by code; impact depends on delivery order.** `backend/app/services/stripe_service.py:86-119,251-323` handles events without an event ledger or ordering check; a delayed checkout completion can mark a canceled subscription active. Reconcile against authoritative subscription state and deduplicate events transactionally; replay duplicates, reverse ordering and payment-failure sequences with signed fixtures.
3. **P1 — uploaded originals and database rows are not atomic, proven by ordering.** `backend/app/api/routes/documents.py:244-280,433-461`: storage upload precedes DB commit and deletion precedes DB deletion. A later DB failure leaves orphaned objects or records with missing originals. Add compensating cleanup plus durable reconciliation/outbox; fault-inject DB/storage failure on both paths and verify recovery.
4. **P1 — background parsing cannot be forcibly stopped, proven by execution model.** `backend/app/api/routes/documents.py:91-99` wraps `asyncio.to_thread` in a timeout; cancellation does not kill the worker thread. The parser (`backend/app/services/document_processor.py:31-61`) can still consume resources on hostile PDFs/DOCX after the timeout; size and page caps are useful but insufficient for decompression/CPU isolation. Use resource-limited subprocess workers and a durable queue, enforce archive entry/expanded limits and terminate on deadline; test malformed, compressed, encrypted and pathological PDFs and ZIPs in a sandbox.
5. **P1 — citations and abstention are prompt instructions, not validated, proven by code.** `backend/app/services/ai_service.py:340-397` returns every retrieved chunk regardless of whether the answer cites or is supported by it. A hallucinated source number or unsupported claim can reach users. Validate citation identifiers and page provenance and add claim-level/manual evaluation; exercise absent answers, wrong numbers, contradictory facts and malicious text. A prompt boundary (`:133-135,349-357`) reduces risk but is not a security guarantee.
6. **P1 — tenant and storage assurance depends on deployment, unverified.** Server uses a privileged client (`backend/app/db/database.py:118-134`) and application-owned JWTs. Ownership filters are present (`backend/app/services/rag_service.py:277-284,325-328`); `scripts/001_init_schema.sql:134-181` enables RLS and revokes browser roles. The test proves a local outsider query is empty, not actual deployed grants, object policies, signed URL privacy, or service-role configuration. Inspect production settings with authorization, enforce private buckets and run two-user read/write/object isolation tests; do not infer a vulnerability without that evidence.
7. **P2 — free-tier counter and provider usage do not bound spend.** See item 1; Pro has no limit (`backend/app/services/stripe_service.py:199-200,221-222`), and analysis may make several calls (`backend/app/services/ai_service.py:176-200`). `tokens_used` is a local tokenizer estimate, excluding provider reasoning and reranking (`:372-374`). Add provider usage telemetry, budgets, cost caps and alerts; verify against invoices and retry counts.
8. **P2 — evaluation cannot substantiate retrieval or reranker claims.** `backend/app/eval/evaluator.py:73-114,148-154` uses the three demo documents, NumPy and a separately gated reranker. `backend/app/services/rerank_service.py:54-57,128-138` silently preserves order when globally disabled or on failures. The historical run says enabled, but does not record actual LLM execution versus fallback. Its very small corpora, cached outputs and repeated context plausibly explain unchanged metrics; the exact historical cause is unproven. Instrument calls/outcomes and use a larger frozen corpus with labeled candidate sets; assert candidate count > K and measure paired rankings with confidence intervals. `docs/EVALUATION_REPORT.md` invalidates historical precision due to its former denominator.
9. **P2 — grading proxies and report language overstate evidence.** `backend/app/eval/metrics.py:14-103` uses substring hits, a phrase list for refusal and lexical overlap for groundedness; neither entails factual support. Three negatives produced one detected refusal (`docs/benchmark_report.json`); undetected does not prove hallucination and 1/3 is not a reliable population estimate. Only truncated answer previews remain. Use independent gold evidence spans, human claim/citation review and both false-refusal and false-answer tests. The generator previously labeled dense+rerank hybrid and asserted an unmeasured latency improvement; this branch corrects those strings.
10. **P2 — multi-document fairness and latency limits.** Retrieval is sequential per document and repeatedly embeds the same question (`backend/app/services/ai_service.py:429-439`); the final selection has at most `RAG_TOP_K+2` slots and reserves in input order (`:47-77,469-471`). The API allows at most five unique documents (`backend/app/schemas/schemas.py:177-186`), so the default eight slots accommodate them, but smaller configured slot counts or direct service callers can favor earlier documents; documents with no retrieved candidates are omitted. Batch embedding, report omissions and test permuted order and nondefault limits.
11. **P2 — process-local jobs and throttling.** FastAPI background tasks (`backend/app/api/routes/documents.py:278-280`) can disappear on process restart; stalled work is only marked failed when a later request runs recovery (`:495-506`). LLM semaphore/pacing are per process (`backend/app/services/llm_limiter.py:29-38,88-105`), so multiple workers multiply effective throughput. Use durable queue and shared quota controls; kill/restart worker mid-job and load-test multiple replicas.
12. **P2 — browser refresh tokens are script-readable.** `frontend/src/store/authStore.ts:39-40,54-55,69-70` stores access and refresh tokens in localStorage; an XSS would expose long-lived refresh credentials. No XSS is proved. Consider HttpOnly Secure SameSite cookies and rotation/revocation, enforce CSP, and test injection and session lifecycle.
13. **P2 — reranking fallback can be reported as success.** `backend/app/services/rerank_service.py:128-138` returns original ranking on errors, while `backend/app/services/ai_service.py:329-335` sets `reranked=True` regardless. Return explicit status and measure fallback rate; inject provider and malformed JSON failures.
14. **P2 — model/cache controls incomplete.** Historically cache omitted model and fallback policy (`backend/app/api/routes/query.py:76-77` before this branch). This branch partitions by primary model and avoids caching fallback responses; retrieval and prompt version changes still require invalidation/versioning, and reranker retains its separate `LLM_MODEL` route (`backend/app/services/rerank_service.py:88-102`). Test deployment configuration changes and cache poisoning/expiry. Fallback has its own privacy implications.
15. **P3 — dependency/build assurance is incomplete.** `backend/requirements.txt` pins direct but not transitive Python packages or hashes; CI (`.github/workflows/ci.yml`) installs resolved dependencies and has no dependency audit job. Frontend has an npm lockfile. Existing `docs/verification/*audit*.json` is historical, not a current security verdict. Lock transitive dependencies with hashes, scan in CI and reproduce clean builds.
16. **P3 — UX assurance is partial.** Upload has labels/error state (`frontend/src/components/dashboard/UploadZone.tsx:19-47`), demo has retry/live status (`frontend/src/pages/DemoPage.tsx:6-91`); 7 component tests do not establish full mobile, keyboard, screen-reader, real provider or offline behavior. Add browser journeys across upload, processing, chat, errors and retry at mobile widths and with assistive technology.

## Verification and limits

Local suite, frontend build and disposable DB results are recorded in the final response. The pgvector script verifies index existence through migrations and functional search but never runs `EXPLAIN`; it cannot prove ANN index usage, recall, or realistic latency. Browser roles were checked locally, not on Supabase. File upload caps input at 20 MB and DOCX declared expansion at 50 MB; empty documents are rejected; identical uploads are not deduplicated. Duplicate behavior, adversarial parsing resource bounds, prompt injection, source correctness, live Stripe ordering, and real UI accessibility remain to be tested. No dependency vulnerability scan or deployed configuration assessment was run during this audit.
