# RAG evaluation plan

The legacy 15-case report is historical and invalidated. Its negative result is one phrase-detected refusal out of three; full answers were not retained, so neither actual false-answer rate nor causes can be reconstructed. Identical metrics do not demonstrate reranking worked: small candidate sets, disabled global setting, provider fallback, identical ordering and cached results are plausible; the artifact does not establish which occurred. The evaluator uses NumPy, not pgvector/HNSW/FTS. Production PostgreSQL runs independent dense and sparse searches and unions candidate IDs before RRF, so sparse can add a chunk missed by dense. SQLite uses a separate lexical method. Prove sparse-only recovery in a disposable Postgres test with >2K distractors and EXPLAIN index plans.

## Frozen, blinded comparison

Build a versioned held-out corpus of at least 100 questions across at least 20 independent documents; split by document, author labels separately from developers, keep answers out of model prompts. Freeze input document hashes, chunk IDs, pages, retrieved context and ordering once per question. Each model gets identical question, instruction, evidence, output budget and standardized parameters where supported; record effective provider parameters. Randomize order and run at least three repetitions without application or provider cache where possible; record cache headers when not controllable. Isolate retrieval comparison from generation comparison: first evaluate exact search vs ANN, FTS, RRF and reranking on labeled IDs; then hold contexts fixed to evaluate models. Include empty context and no relevant result as distinct cases. Current offline plumbing: `python3 scripts/mock_model_comparison.py` runs 24 synthetic cases, 12 positive and 12 absent; the negative question is repeated across contexts, so these are plumbing fixtures rather than 24 independent negative scenarios. It is mock-only, does not use models, gives no quality or latency evidence, and is not a substitute for the blinded corpus or a live runner.

Case mix: at least 25 direct facts, 15 paraphrases, 15 multi-hop, 15 cross-document agreement/conflict/silence, 15 unsupported/out-of-domain, 10 adversarial prompt injections, and 5 ambiguous/partial evidence. Add scanned/blank/encrypted/corrupt/oversized PDFs and DOCX ZIP expansion, duplicate and empty files, page boundaries, long documents, multilingual terms, semantically close distractors and hard negatives. Test two tenants with identical names, forbidden IDs, storage paths, cache hits and document deletion; permute selected-document order and test more documents than context slots. Include prompt injection in filenames, history and chunks. Label expected refusal, atomic claims, gold supporting spans, source IDs and pages, not just keywords.

For each answer retain model ID/version, dataset/hash, prompt revision, exact context IDs, request status, retries, provider response usage (input/output/reasoning/cached), latency, pricing date, output, source links, structured-output validity and error class. Measure answer accuracy and false refusal, faithfulness (supported atomic claims / all claims), correct abstention and false answer on negatives, citation precision (supported cited claims / cited claims), citation recall (supported claims with valid citations / claims requiring citation), JSON parse/schema validity, p50/p95 wall time and error rate; report numerator/denominator, uncertainty intervals and per-category scores. Measure each retry and failed attempt costs; costs = input tokens * input price / 1M + output tokens * output price / 1M, including reasoning where billed. Human reviewers independently adjudicate ambiguous answers and citations, blind to model, with disagreements resolved and recorded. Do not count lexical similarity as faithfulness or an unsupplied token usage as zero.

Proposed launch gates, not existing results: zero observed cross-tenant exposures in exhaustive automated negative tests; ≥95% human-reviewed claim support and citation precision, ≥90% answer accuracy on answerable questions, ≥95% correct abstention with ≤5% false refusal on answerable cases, ≥99% JSON validity, <1% request errors. Define latency and cost budgets from actual traffic and include p95 and confidence intervals; avoid claiming a pass from small samples. Any security failure blocks release. Live testing requires explicitly approved provider spend, keys with appropriate data retention terms, and a disposable dataset/database. Do not send private customer documents to a new provider until terms and consent are reviewed.

## Citation hardening: controlled offline evidence

On branch `codex/audit-2026-followup`, the answer service now requests bracketed source IDs and validates them against the exact ordered chunks supplied to generation. If a page is supplied, it must match that chunk; if omitted and known, it is inserted. No evidence or a model's exact insufficient-evidence response yields an explicit abstention. Invalid, absent, or malformed citation references yield a distinct request-to-retry message; that distinction avoids asserting that evidence is absent when the reference itself is the problem. Citations with a valid number and page are **reference-valid only**, not verified as supporting the claims, and uncited claims accompanying a valid citation are not automatically identified. Citations returned in old history are not retroactively validated.

A controlled comparison with a single retrieved chunk, `Warranty is 24 months` on page 2, used mocked generation and the committed `HEAD` implementation as the before state. The fabricated ID, wrong page, and uncited answer were passed through before and blocked after (3/3 selected failure examples); a missing page was filled correctly after (1/1 example). A false claim with a real citation remained accepted after (1/1 deliberately unsupported example). These are contract examples, not estimates of model accuracy or faithfulness. No answer in this experiment was human-reviewed for quality (0 reviewed); no live model was called. Automated regression tests also cover conflicts, multi-document mapping, malformed references, malicious text, and reranking failures.

Document text, history, filenames and questions are serialized as untrusted JSON in a user message; the model receives the behavioral boundary separately as a system message. This is defense in depth, not proof against prompt injection. The model can still follow hostile content, invent a claim while citing a real source, misname a document, omit a needed citation on one claim, or wrongly abstain. Format adherence and the false-abstention trade-off must be measured live. Reranking is disabled by default. When enabled, telemetry distinguishes executed, skipped and failed; incomplete or invalid scores now fall back to original retrieval order and are reported as failed. Generation fallback, retrieval results and abstention reasons are logged without document content. The API response shape is unchanged.

The answer cache namespace changed from v3 to v4 so older unvalidated cached answers cannot bypass the new checks. A first repeat query after this update may incur a new provider call and usage; billing policy and quota code are unchanged. The v4 cache still caches citation-validation abstentions for its existing TTL, so retries may return that response until expiry. This is a known UX trade-off to measure. The existing mock comparison script is not a live provider runner: an approved live run still requires a frozen held-out corpus, a provider runner capturing actual token usage and errors, and independent human claim/citation adjudication. The implementation is suitable for a controlled diagnostic benchmark after those are prepared, not yet for a publishable model comparison or a claim of production readiness.
